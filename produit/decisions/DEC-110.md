## Décision
Le fond de carte utilise le paquet pub `maplibre` 0.3.7+1 (MapLibre Native, rendu GPU, tuiles vectorielles) avec un fichier de tuiles Protomaps au format PMTiles copié dans le stockage de l'app au premier lancement, lu par `pmtiles://file://<chemin>`.
**Statut du spike : choix fondé sur les sources et la documentation, pas encore vérifié sur téléphone.** Il se confirme ou se corrige à la démo (voir « À vérifier »).

## Critères et comparaison
| Critère | `maplibre` (retenu) | `maplibre_gl` 0.27.1 | `flutter_map` + `vector_map_tiles_pmtiles` |
| --- | --- | --- | --- |
| Android | natif, OK | natif, OK | Dart pur, OK |
| Lecture PMTiles | oui, côté natif (MapLibre Native ≥ 11, `pmtiles://`) | oui, via le même moteur natif | oui, paquet `pmtiles` |
| Hors ligne | fichier local, aucun réseau requis | idem | fichier local à brancher soi-même |
| Maintenance | publié le 29/10/2026, très actif | actif, éditeur maplibre.org, 150 000 téléchargements / 30 j | `vector_map_tiles_pmtiles` : dernière version 14/10/2024, `vector_map_tiles` : 16/08/2024 |
| Fluidité | rendu natif GPU | idem | rendu vectoriel Dart, plus lent |
| Emprise bornée (CF3) | `MapOptions.maxBounds` | `cameraTargetBounds` | `CameraConstraint` |
| iOS | prévu (`maplibre_ios`) | prévu | prévu |

`maplibre_gl` reste le repli : même moteur natif, paquet plus ancien et plus utilisé.
La pile `flutter_map` est écartée : les deux plugins de tuiles vectorielles ne sont plus publiés depuis octobre 2024.

## Point d'attention
`maplibre` 0.3.7+1 embarque MapLibre Native Android `13.5.+`. La lecture directe d'un PMTiles dans les assets de l'APK (`pmtiles://asset://`) n'arrive qu'en 13.7.1. Le spike contourne : copie du fichier de l'asset vers `getApplicationSupportDirectory()`, puis `pmtiles://file://`. Le fichier est donc présent deux fois sur le téléphone (APK et copie). À reprendre quand le paquet passera en 13.7+ (ticket tuiles embarquées).

## Taille du fichier de tuiles
**Non mesurée dans cette PR.** L'extraction n'a pas pu être faite depuis l'environnement de l'agent (l'outil `pmtiles` n'a pas pu être installé). Commande à lancer, avec l'outil officiel `pmtiles` (protomaps/go-pmtiles) :

```
pmtiles extract https://build.protomaps.com/20261030.pmtiles lyon.pmtiles \
  --bbox=4.77,45.70,4.93,45.80 --maxzoom=15
ls -l lyon.pmtiles
```

Reporter ici la taille obtenue et le niveau de zoom maximal retenu. L'emprise de test (4,77 / 45,70 / 4,93 / 45,80) est à confirmer (QO-802) ; elle contient Bellecour (45,7578 ; 4,8320).

## À vérifier sur téléphone, en mode avion
1. `cp lyon.pmtiles apps/mobile/assets/spike/` puis `flutter run -t lib/spike/main_spike_carte.dart` depuis `apps/mobile/` (fichier ignoré par git).
2. Après un premier lancement, passer en mode avion, fermer et relancer l'app : le fond s'affiche.
3. Déplacement et zoom fluides ; impossible de sortir de l'emprise ; aucune demande de permission ; attribution visible.
4. Si `pmtiles://file://` est refusé par MapLibre Native 13.5, essayer `maplibre_gl`, ou forcer la dépendance native en 13.7.1.

## Conséquences
- Le code du spike (`apps/mobile/lib/spike/`) est jetable ; les tickets « tuiles embarquées » et « carte plein écran » le remplacent.
- Le style du spike est minimal (eau, parcs, bâtiments, routes, sans libellés) ; le style unique est un autre ticket.
- Les tuiles ne sont pas committées (`*.pmtiles` ignoré dans `apps/mobile`).
